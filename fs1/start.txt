## Browser
Open http://localhost:8080

## Expected flow in the WS log
 1. WS connects → status dot green
 2. Server sends `identify` (machine guid on the USB link) → sim runs the served
    bootstrap.py (with _AVAILABLE_MACHINES injected — sim-only fallback; the real
    knob reads its own /fs1/locations) → the location picker renders on the knob
    display → you pick a location → bootstrap_response back
 3. Server matches that location to a location config → sends config → sim acks
 4. Server sends launcher.py → sim builds app UI, prints launcher_ready

## Simulator specifics
  - No dropdown / Start button anymore — bootstrap runs as soon as it arrives.
  - Optional "Machine GUID" text field mimics the USB path: type e.g. `mac-m1-max`
    before the bootstrap arrives and that machine's location is preselected.
  - No wifi in the browser, so the wifi-filter path only runs on the ESP32.
  - The sim has no /fs1 yet, so bootstrap uses the server-injected location list.
    On the real knob, bootstrap reads /fs1/locations directly.

## Add a location config
Create fs1/locations/<name>.json. See existing files for the schema.
Key fields: `location` (shown in the bootstrap picker), `wifi.ssid`
(filters the picker when the knob is standalone on wifi), `wifi.password`
(what the knob joins after you pick), per-location `defaults`
(backlight/haptic/sound), and `machine_guid` (matched against the PC's OS
machine id on the USB link).
Restart server.py — it picks up new configs on next connection.

## How the knob picks its location (real hardware)
  - `main.py` runs `/fs1/bootstrap.py` first (encoder/touch input fed to it,
    60s timeout), then hands off to the launcher with the choice saved to
    `/fs1/.state.json`.
  - Reads /fs1/locations from its own flash partition at boot — no server needed
    to know what locations exist.
  - Plugged into a PC over USB → the PC's server sends `identify` with its OS
    machine id (Win: registry MachineGuid · Mac: hardware UUID · Linux:
    /etc/machine-id) → bootstrap preselects that machine's location; wifi join
    is skipped (USB link is up).
  - Standalone on wifi → bootstrap scans nearby wifi and shows only the
    locations whose configured wifi is reachable; picking one **joins that
    wifi** on the spot (`wifi_connect.connect`) and reports it in
    `bootstrap_response` (`"wifi":"connected"`). No PC server needed after that
    — the knob can talk to home devices (lights, curtains) directly.
  - Otherwise → all locations are shown.

## settings.json (on the knob, /fs1/settings.json)
  - `boot_backlight` — fixed level so the picker is visible in the dark.
  - `websocket_uri` — the PC server address when on wifi (PC-app path only).
  - `static_ip` — USB link addressing (knob 10.10.10.1 / pc 10.10.10.2).
  Wifi credentials and per-location defaults live in fs1/locations/, not here.
